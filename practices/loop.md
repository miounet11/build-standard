# 七步创建环

程序是一环一环做出来的，不是一次设计完再实现。非平凡改动必须走满七步。缺一步就停，不看动机。

验收侧的同一环见 [ship-standard / probe](https://github.com/miounet11/ship-standard/blob/main/dimensions/probe.md)。这里写的是**创建时怎么用它**。

---

## 一句话

**诊断 → 规格 → 计划 → 红灯 → 最小绿 → 门禁证据 → 反思。跳过任一步，这笔改动不算创建完成。**

---

## 步骤

| 步 | 创建时做什么 | 留下什么 |
|----|--------------|----------|
| 1. 诊断 | 读代码、现场、旧风险。写 3 条缺口 | 用户影响，不是「代码丑」 |
| 2. 规格 | 用现在时写不变量；写不出测试的句子删掉 | 规格文件或 PR 里的不变量列表 |
| 3. 计划 | 拆 P0 / P1 / P2，每项有完成定义 | 本轮只做 P0 |
| 4. 红灯 | **先提交失败的测试 / 探针 / 清单项** | 第一笔提交是红的 |
| 5. 绿灯 | 最小改动让红灯变绿 | 见 [smallest-green](./smallest-green.md) |
| 6. 验证 | 跑本范围门禁；贴证据 | CI 或约定的共享跑法，本机绿不算 |
| 7. 反思 | 新缺口进风险册；现实和规格不符就改规格 | 同一笔提交，不留到「以后」 |

平凡改动（错字、注释）可以不走满环，但不得借此改行为。

---

## 创建时的顺序错误

| 错序 | 后果 |
|------|------|
| 先写一大摊实现，再补测试 | 测试会迁就实现，灯是假的 |
| 先改三层再看红不红 | 说不清根因，下一会话无法复用 |
| 规格写在聊天里 | 下一会话从零重讲 |
| 反思留到下周 | 机构记忆丢失，同一坑再付一次钱 |

---

## 禁止

- 「先做出来，测试以后补」
- 用任务清单打勾代替门禁绿
- 一笔提交同时改协议、UI、编码、进房

---

## 产出

红灯提交、绿灯提交、规格/风险的同一笔更新、门禁证据。
