# 人定做成，Agent 执行

这些程序是人与 Agent 一起创建的。能持续出活，是因为**所有权没搞反**：人拥有方向和完成定义，Agent 拥有在仓库规则里的执行力。

---

## 一句话

**人说清「这版做成什么样、什么不做」。Agent 在仓库记忆里跑闭环。Agent 不得自己宣布上线。**

---

## 分工

| 角色 | 必须做 | 不得做 |
|------|--------|--------|
| **人（Owner）** | 定北极星、本轮范围、真路径怎么验、能不能发给第二台机器 | 把「感觉可以了」当成门禁 |
| **Agent** | 读仓库记忆、走七步、写最小 diff、跑门禁、把新坑写回文件 | 发明范围、关生产守卫、把密钥写进仓库 |
| **仓库** | 记住身份、命令、规格、风险、基线 | 空仓库 + 只靠聊天上下文 |

Agent 换一次会话、换一个模型，只要仓库记忆在，创建就能接着干。聊天记录不是记忆。

---

## 一次创建会话怎么开

1. 人用现在时说完成定义（能写成测试的句子）。
2. Agent 先读身份文件和合同目录，再动代码。
3. 范围外的想法记 backlog，本轮不做。
4. 结束时：代码、规格、风险、探针在同一状态；人对照门禁决定是否进入真路径。

人中途改口（「不要无限重试，两振退役」）是正常创建。Agent 应改合同和代码，而不是只改一处 if。

---

## 禁止

- 对人说「已上线」但用户通道没有这版
- 没有完成定义就开始大重构
- 把 Owner 的口头例外写成永久默认（例如生产开 mock）
- 为了显得勤快，同时开三条无关战线

---

## 产出

一页完成定义、本轮 P0 列表、Agent 按七步留下的提交。
