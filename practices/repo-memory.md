# 仓库当记忆

创建会跨很多会话。模型上下文会丢，人也会忘。**能接着创建的唯一可靠物是仓库。**

---

## 一句话

**下一会话打开仓库，必须能回答：这是谁、命令怎么跑、合同在哪、现在坏在哪、下一步做什么。**

---

## 最低记忆集

| 文件 | 记住什么 | 谁更新 |
|------|----------|--------|
| 身份 / 规则（如 `clavue.md`、`AGENTS.md`） | 产品是谁、目录、命令、权威链 | 结构变了就再生，不要手写一份过期的 |
| 路线图 | 做什么、顺序、本季度不做 | 范围变了就改，不让计划只活在聊天 |
| 规格 | 每个产品纬度必须为真的句子 | 和代码同一笔 |
| 风险册 | 打开的缺口；关闭的行留下 | 发现就加，关闭不删 |
| 门禁 | 哪些灯 warn、哪些 block | 灯稳定后再升级阻断 |
| 状态页 | 「现在坏在哪」 | **生成**，禁止手改进度 |
| 基线 | 包体、分数、探针快照 | 改阈值和改代码同一笔 |

没有合同目录时，每次创建都从聊天重讲，产品力无法复利。见 [ship-standard / compound](https://github.com/miounet11/ship-standard/blob/main/dimensions/compound.md)。

---

## 权威链

每个问题只认一个权威，写在身份文件里。例如：

- 产品方向 → `product/roadmap.md`
- 桌面源码 → `src/`
- 线协议 → `shared/` + 协议文档
- 状态数字 → 生成器，不认手改的 `STATUS.md`

代码和规格不一致，**必有一方错**。解决的那一笔两边一起改。

---

## 创建时怎么用记忆

1. 开会话先读记忆，再问人「还缺哪句完成定义」。
2. 改行为先改规格，再改代码，再改探针。
3. 新坑写进风险册，不要只写在回复末尾。
4. 里程碑进度以路线图勾选和生成状态为准。

---

## 禁止

- 重要决定只出现在聊天，不落文件
- 手改生成的状态页
- 同一事实在 README、规格、代码注释里各写一套且不互相指认权威

---

## 产出

可被下一会话直接读的身份文件和合同目录。
